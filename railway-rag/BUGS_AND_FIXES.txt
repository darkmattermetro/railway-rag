1. clear_cache on success destroys own category's cache
────────────────────────────────────────────────────────────────────────

  File:     ingest.py:733

  Before:
    def ingest_pdfs(...):
        ...
        clear_cache(category, delete_chunks=True)
        return {"chunk_count": chunk_count, "category": category}

    Every successful run wipes the chunk cache.  If you have 100 PDFs
    and want to add file #101, the existing 100 get fully re-processed.
    Incremental indexing is broken — you start from zero every time.

  After:
    Remove the clear_cache call from the success path.  Cache is only
    cleared when user explicitly clicks "Start Fresh" or passes --fresh.

  Change:  Remove one line (ingest.py:733)


2. CPU fallback in _embed_batch still uses GPU embeddings for existing index
────────────────────────────────────────────────────────────────────────

  File:     ingest.py:525-541

  Before:
    def _embed_batch(batch_docs, vs):
        try:
            if vs is None:
                return FAISS.from_documents(batch_docs, embeddings)
            vs.add_documents(batch_docs)          # uses GPU embeddings
            return vs
        except (RuntimeError, torch.cuda.OutOfMemoryError):
            cpu_embeddings = HuggingFaceEmbeddings(...)
            if vs is None:
                return FAISS.from_documents(batch_docs, cpu_embeddings)
            vs.add_documents(batch_docs)          # STILL uses GPU embeddings!
            return vs

    On OOM for the second+ batch (when vs already exists), the except
    block creates cpu_embeddings but still calls vs.add_documents()
    which uses the GPU embeddings stored inside vs.  Same OOM repeats.

  After:
    On OOM for existing vs, create a new CPU FAISS index from the
    failing batch, then merge it into vs with vs.merge_from().

  Change:  ~10 lines in ingest.py — replace add_documents with
           merge_from in the CPU fallback path

5. Progress bar double-counts pages on GPU→CPU fallback
────────────────────────────────────────────────────────────────────────

  Files:    ingest.py:305,311 — local_builder.py:176

  Before:
    _convert_page calls callback(page_no, "GPU", None) at line 305.
    On OOM, it calls callback(page_no, "CPU", "OOM") at line 311.
    Both fire PAGE_PROG events.  The handler increments global_pages_done
    every time.  So a page needing fallback is counted twice.

    For OCR-heavy documents, the bar hits 100% at ~50% real progress,
    then stalls.  ETA goes negative and disappears.

  After:
    local_builder.py: increment global_pages_done only on PAGE_DONE,
    not PAGE_PROG.  ingest.py: emit PAGE_DONE once per page after the
    conversion decision (after fallback or CPU path).

  Change:  ~8 lines across ingest.py and local_builder.py


6. build_index.py resume print shows SHA-256 hashes, not filenames
────────────────────────────────────────────────────────────────────────

  File:     build_index.py:126

  Before:
    print(f"   Completed: {', '.join(sorted(matching))}")

    The user sees:
      Completed: a3f2b8c1...d4e5f6, c7d8e9f0...a1b2c3

  Change:  ~5 lines in build_index.py

7. PdfiumError not caught in page-resolution check
────────────────────────────────────────────────────────────────────────

  File:     ingest.py:288-298

  Before:
    except (OSError, ValueError) as e:
        return True

    pypdfium2.PdfDocument() raises PdfiumError for corrupt PDFs,
    missing permissions, unsupported formats.  The except clause
    doesn't catch it — PdfiumError propagates and crashes ingestion.

  After:
    Import PdfiumError and add it to the except tuple.  Log at ERROR
    level and return False (CPU safe default) on failure.

  Change:  2 lines (import + except)


8. Mid-stream failure doesn't update model exhaustion state
────────────────────────────────────────────────────────────────────────

  File:     model_selector.py:321-322

  Before:
    yield first_chunk
    yield from stream_iter      # if this fails mid-stream...
    return
    ...
    except Exception as e:
        # model/key state NOT updated for mid-stream failures

    If streaming succeeds for the first chunk but fails mid-response
    (e.g., network timeout), the exception propagates through the
    generator without calling _mark_key_exhausted or
    _mark_model_exhausted.  Next query retries the same bad model/key.

  After:
    Wrap yield from stream_iter in try/except that updates exhaustion
    state on failure then re-raises.

  Change:  ~8 lines in model_selector.py


9. FAISS index hash loads entire files into memory (OOM risk)
────────────────────────────────────────────────────────────────────────

  Files:    app.py:74-76, smoke_test.py:32-34

  Before:
    actual.update((index_path / "index.faiss").read_bytes())
    actual.update((index_path / "index.pkl").read_bytes())

    Path.read_bytes() loads the entire file into RAM.  For a 500 MB
    index.faiss + 100 MB index.pkl, this is a 600 MB spike.  Combined
    with embedding model (~100 MB) and cross-encoder (~200 MB), this
    can OOM on Streamlit Cloud (1 GB RAM).

  After:
    Stream the file in 64 KB chunks:
      with open(path, "rb") as f:
          while chunk := f.read(65536):
              actual.update(chunk)

  Change:  ~12 lines — extract _hash_file() helper, use in both places


10. No timeout on converter.convert() — indefinite hang
────────────────────────────────────────────────────────────────────────

  File:     ingest.py:306,313,323,328,335,351,355

  Before:
    return converter.convert(page_path).document   # no timeout

    A corrupt PDF page, hung GPU kernel, or stalled I/O can block
    converter.convert() forever.  No way to abort — the entire build
    hangs until the process is killed.

  After:
    Wrap conversion in ThreadPoolExecutor with a 300-second timeout.
    On timeout, log the error and raise for the caller to handle.

  Change:  ~15 lines in ingest.py (_convert_with_timeout wrapper)


11. _convert_page_force_ocr OOM path silent (no callback, no return)
────────────────────────────────────────────────────────────────────────

  File:     ingest.py:336-342

    except RuntimeError as e:

            gc.collect()

    The ConversionError handler (lines 343-351) correctly calls

  Change:  ~4 lines in ingest.py


12. Unsafe FAISS deserialization remains enabled
────────────────────────────────────────────────────────────────────────

  Files:    app.py:112, smoke_test.py:51

  Before:
    vector_store = FAISS.load_local(
        str(index_path), embeddings,
        allow_dangerous_deserialization=True,
    )

    The FAISS index.pkl uses Python pickle.  An attacker who can write
    to the index directory can inject arbitrary code execution.  The
    hash check (index.hash) mitigates tampering but doesn't protect
    against a compromised build machine.

  After:
    Keep as-is for now (hash check + README warning are sufficient for
    this project's threat model).  Long-term: switch to safetensors or
    signed artifact verification.

  Change:  None (documented as accepted risk)

21. Broad except Exception in runtime paths
────────────────────────────────────────────────────────────────────────

  Files:    app.py:320, app.py:536

  Before:
    except Exception as e:
        st.error(f"Failed to load index: {selected_index_name}")
        ...

    except Exception as e:
        st.error("All LLM providers...")

    Catch-all Exception hides root causes.  A programming bug
    (e.g., KeyError, TypeError) gets caught and shows a generic
    error instead of crashing with a traceback.

  After:
    Catch specific exception types.  For index loading: catch
    RuntimeError, FileNotFoundError, ValueError.  For LLM: let
    non-API exceptions propagate.  Include structured error info.

  Change:  ~5 lines in app.py
